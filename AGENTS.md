# Air — рабочие договорённости

- Пользователь выбрал направление Air: компактный обзор с раскрытием подробностей; сохранять визуальную связь между режимами и темами.
- Источник требований: `docs/superpowers/specs/2026-10-14-air-design.md`. Различать согласованные функции, предлагаемые параметры и проверенные возможности.
- Репозиторий пока содержит документацию и макеты. Не выдавать картинки, демонстрационные данные и запланированные функции за работающее приложение.
- Не приписывать показатели процесса конкретной вкладке Safari без проверяемого сопоставления. Не выдавать измерения JavaScript-кучи за полную память страницы.
- Завершение процессов выполняется только по явному действию пользователя приложения. Для проверки не завершать его реальные приложения: использовать специально запущенные тестовые процессы.
- Перед отправкой сигнала повторно проверять идентичность процесса, а не полагаться только на сохранённый PID.
- Держать единицы и шкалу CPU согласованными между обзором, процессами, историей и правилами.
- Не сохранять реальные адреса вкладок, дампы процессов, ключи подписи, токены и локальную историю мониторинга в Git.
- При появлении кода документировать сборку и выполнять проверки, соответствующие изменениям. Для правок документации достаточно проверки ссылок, файлов и diff.
