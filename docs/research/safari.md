# Safari: вкладки и расход ресурсов

Дата исследования: 14 октября 2026 года. Основной браузер пользователя — Safari.

## Что удалось подтвердить по документации

- [SFSafariTab](https://developer.apple.com/documentation/safariservices/sfsafaritab) предоставляет работу со страницами вкладки, переключение, навигацию и закрытие. В перечисленных методах нет CPU, полной памяти вкладки или идентификатора её системного процесса.
- [Web Inspector / Timelines](https://webkit.org/web-inspector/timelines-tab/) измеряет CPU и память исследуемой страницы во время записи. Некоторые измерения сами влияют на производительность.
- [Документация Apple по Web Inspector](https://developer.apple.com/documentation/safari-developer-tools/web-inspector) описывает подробное профилирование страницы. Это не подтверждает наличие поддерживаемого массового API мониторинга всех вкладок для обычного стороннего приложения.
- [Web Inspector и Site Isolation](https://docs.webkit.org/Deep%20Dive/Web%20Inspector/SiteIsolationExplainer.html) описывает межпроцессную инспекцию: модель «одна вкладка = один процесс» нельзя принимать как универсальную.

Вывод ограничен просмотренными интерфейсами: простой готовый путь точного сопоставления не найден. Это не доказательство невозможности.

## Вопрос для прототипа

Можно ли на целевой версии Safari поддерживаемыми средствами получить достоверную связь между вкладкой и наблюдаемыми системными процессами, пригодную для обычного ежедневного использования?

## Условия эксперимента

Отдельные тестовые страницы и процессы, без закрытия реальных вкладок пользователя. Проверить две вкладки одного сайта, разные сайты, навигацию, фон, закрытие вкладки, перезапуск Safari и приватный режим. Не собирать личные URL в репозиторий и логи.

Зафиксировать использованный интерфейс, необходимые разрешения, полноту связи, неоднозначности, накладные расходы и поддерживаемую версию Safari. Оценить расширение отдельно от мониторинга системных процессов.

## Критерий принятия

Название вкладки и показатели связываются проверяемо, а общие ресурсы не дублируются и не приписываются одной вкладке произвольно. Неоднозначность показана пользователю. Закрытие вкладки выполняется как действие браузера, а не как безусловное уничтожение общего процесса.

Если этот критерий не выполняется, первая версия показывает процессы Safari, а подробное профилирование страницы остаётся отдельным исследовательским сценарием.
